# Dependency Management

Every dependency is code you now maintain. Add reluctantly, pin deliberately.

## When to use
- Adding a library to solve a problem.
- Upgrading for a security fix or feature; removing dead packages.
- Auditing the dependency tree.

## Workflow
1. Check first whether the standard library or an existing dependency already covers the
   need. Only then look outward.
2. When choosing a package, weigh: maintenance activity, download/usage, licence,
   transitive weight, and last release date. Prefer fewer, smaller, well-kept deps.
3. Add with the repo's tool so the lockfile updates coherently
   (`bun add`, `npm install`, `pip install`, `cargo add`, `go get`). Never hand-edit
   the lockfile.
4. Pin according to repo policy: exact versions or ranges consistent with what is there.
5. After adding/upgrading, run install clean, typecheck, build and tests. A major bump
   needs a changelog read for breaking changes.
6. For removal, confirm nothing imports it (`grep` the package name) before uninstalling.
7. Audit: run the ecosystem audit (`npm audit`, `bun audit`, `cargo audit`, `pip-audit`)
   and note licence and bundle-size impact.

## Pitfalls
- Hand-editing or deleting the lockfile; it must be regenerated by the tool.
- Adding a heavy framework for a small utility.
- Upgrading a major version across the tree without reading breaking-change notes.
- Introducing a copyleft licence into a permissive project without a decision.
- Committing `node_modules` or vendored dependencies.

## Verify
- Install, typecheck, build and tests pass after the change.
- The lockfile is committed and consistent with the manifest.
- The audit reports no new high/critical advisories; bundle size did not regress unexpectedly.
